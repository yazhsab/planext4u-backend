# Private media malware scanner

The media owner requires a private Unix socket. ClamD TCP traffic is unauthenticated; never expose it to untrusted networks. The protocol and framing follow the [official ClamD guide](https://docs.clamav.net/manual/Usage/ClamdProtocol.html). The local engine and updater use UTC because VERSIONCOMMANDS timestamps have no timezone suffix. Preserve UTC in remote deployments.

`CLAMAV_MAX_SIGNATURE_AGE` defaults to 48 hours and accepts 1–168 hours. Startup, `/readyz`, and each scan validate the loaded engine/database timestamp and INSTREAM support. Missing/malformed/future dates or an exceeded age fail closed. A CLEAN result is checked again before publication. A failed check leaves the upload pending, with no private download access; restoring a healthy scanner allows retry. Changing file mtimes or observing a running updater does not establish loaded-definition freshness.

Scrape media readiness at least every 30 seconds and export OTLP metrics through the existing collector. Load `deploy/observability/alerts/media-scanner.yaml` alongside the existing SLO rules. `planext4u.media.scanner.ready` is 1/0 and `planext4u.media.scanner.checked_at` is Unix seconds. The rules assume downstream dot-to-underscore name translation and the existing `service_name` resource label convention. Configure and validate the downstream OTLP/Prometheus translation before enabling remote alerts. No identity, asset path or scanner response is a metric label.

For either alert, check media `/readyz`, the engine socket permissions/group, the UTC clock and the updater's official-signature verification/reload logs. Query VERSIONCOMMANDS over the private socket and compare the loaded database date with the configured age. Check disk/memory and update connectivity. Keep the pinned supported engine updated through the normal release process. Restore readiness only after the daemon loaded verified official definitions; do not increase the age limit to silence an unexplained outage. Retry pending documents through their owning API. Do not mark them READY manually or grant public object access.

Local proof uses actual S3/ClamAV and advances only the test consumer clock to exercise stale rejection/retry. The harmless EICAR fixture establishes detection separately. The SDK gauge regression proves healthy/failure recording. `promtool test rules deploy/observability/tests/media-scanner.test.yaml` validates healthy, sustained failure, recovery, missing telemetry and stopped-check timelines. These tests follow the [official rule-test format](https://prometheus.io/docs/prometheus/latest/configuration/unit_testing_rules/). The test tool is the pinned official Prometheus 3.15.1 image (see the completion receipt). The rules target ClamAV mode; an HTTP scanner bridge needs equivalent freshness/readiness telemetry before enabling its route. External collector translation, live alert evaluation, paging delivery and a remote operational drill remain release evidence, not implied by local rule tests.
