# Customer web sessions and messaging privacy scope

An opt-in customer-web owner operation now removes encrypted browser session credentials for the due deletion request's exact tenant, account and country. Identity supplies that scope only while the country policy and owner task are ready and no legal hold is active. The scrub waits for concurrent session writes, deletes all matching sessions, records an immutable `RETAINED` receipt and fences later creation or rotation into that scope. A retry verifies that no matching credentials returned. Other countries, accounts and guest sessions remain outside this owner operation. The runtime role cannot call the scrub or read its owner evidence. The web session store's readiness now requires the fence migration.

Disposable PostgreSQL tests cover missing policy, hold, a queued registration race, foreign country and subject, token invalidation, retry, direct reintroduction, rollback refusal and more than 10,000 matching sessions. The large-session case removed an artificial retry dead end; the subject index has the matching non-guest predicate and the receipt fence has a scope index. This is partial local credential removal, not terminal deletion or backup erasure.

New notification outbox events now carry indexed tenant/country/subject lookup metadata outside the event envelope. The messaging owner validates that the metadata belongs to a notification delivery and keeps it immutable while dispatch state changes. Notification's transactional writer supplies the metadata from its own delivery row. Existing outbox rows and other producers remain unclassified and retain their replay and deduplication behavior. Arbitrary legacy envelopes and JetStream copies still require a governed mapping and retention design before messaging can safely scrub or attest erasure.

The [JetStream publisher](OUTBOX_INBOX_DLQ_FOUNDATION.md) additionally verifies the live primary stream's bounded retention and absence of server-side copy settings at startup and before each publish. A disposable NATS drift test denies publication while the stream has unbounded retention and resumes after the policy is restored. This is a forward retention guard; previously published events, external subscribers/copies, backups, a policy change between check and acknowledgment and unclassified legacy envelopes remain open.

Vendor field check-ins now require a live source operator session, an active participant territory binding and an explicit current `resource.command` staff assignment for every actor role. The participant queue offers `FIELD_CHECK_IN` only with that assignment. Country-administrator review and approval authority remains separate. Disposable PostgreSQL cases cover an unassigned country-admin denial, assigned success, revoked replay and the existing regional journey.

The complete source-matched backend gate passes 27 PostgreSQL targets and 155 fresh/rollback migrations. The redeployed local stack passes health, 264 API checks and 85 regional/private-review journeys. No persistent customer session was scrubbed, financial fixture reset, provider activated or iOS build attempted. Media's separate [versioned purge plan](MEDIA_VERSIONED_PURGE_PLAN.md) remains open.
