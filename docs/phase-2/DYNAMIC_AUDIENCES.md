# Dynamic organization audiences

An audience group contains a territory/organization node, eligible job roles, an optional descendant scope, active state and optimistic revision. Membership comes from current active staff assignments and active ancestors. A participant's role change, suspension, ancestor deactivation or group edit affects the next read. Membership does not grant record permissions. A page must match its existing PUBLIC/CUSTOMER/VENDOR/RIDER audience and at least one configured group; an empty group selection preserves the existing role behavior.

The canonical organization workspace provides scoped group creation/editing and a current membership check. The CMS page editor saves group references through the normal draft and independent publication flow. Unavailable group metadata preserves existing references. Read-only staff cannot edit or preview membership. All writes and previews require CSRF, actual MFA and fresh authentication; the owning transaction holds live operator account/session locks before the organization lock. Current staff-management scope is required over both old and new nodes for a move. Criteria versions and organization audit commit atomically.

The configuration service executes a bounded boolean membership function using its restricted runtime role. It receives no staff/group table access. Published snapshot caching never caches membership. Direct page and bootstrap reads use the gateway-derived tenant, country, identity and base roles; query/body authority does not participate. Unassigned, suspended and foreign-scope identities cannot force membership. A membership outage returns a visible retryable failure rather than protected content or fabricated success. Responses use no-store.

The mobile customer bootstrap treats audience-derived service rails as live presentation. They are excluded from serialized/persisted configuration and filtered from offline fallback, including an old in-memory cache. A new read immediately clears them, and superseded responses cannot restore them. Published education content is read online and stores completion metadata rather than page content. A synthetic native cache probe exercises the normal customer cache writer plus independent file/KeyStore readback in an isolated namespace; it does not claim a real provider or native audience enrollment journey.

Current bounds are 32 job roles per group, 16 groups per page, 64 pages per configuration, 1,024 batched membership questions and a three-second database read timeout. The group listing refuses more than 2,000 country records rather than truncating. Full large-directory pagination and broader participant/master administration remain open work. No statutory retention rule, offline membership permission, external identity proof or Phase 2 exit follows from this increment.

Acceptance evidence is recorded in the Phase 2 register. The local browser scenario uses normal group/staff/CMS commands and independent publication, with explicit synthetic operator MFA, source-session revisions and trusted gateway-context fixtures on the internal configuration origin. Initial empty configuration belongs only to its fresh synthetic tenant. Accepted criteria/publication/audit history is retained after that tenant is retired; main-tenant configuration and financial seeds are preserved.

Normal organization writes now use the same account/source-session commit lock as audience writes. The authenticated BFF marks its actor as requiring live proof; JSON cannot disable that check. This covers nodes, job roles, assignments, invitations and business-territory bindings through the common mutation boundary. Trusted in-process test/bootstrap actors remain distinct from authenticated HTTP operators. Source-proof denial and concurrent queued staff/audience revocation are covered by the new isolated PostgreSQL regression; deployment/browser results remain separately recorded.
