# Notification privacy and media runtime access

The notification owner now has an opt-in, country-scoped partial scrub for a due deletion request. Identity migration `000023_notification_erasure_scope` gives only the notification owner the locked request's tenant, subject, country and current policy, plus a `RETAINED` receipt capability. Notification migration `000006_privacy_push_token_scrub` removes matching push-device token rows, suppresses matching queued deliveries, refuses to run while a delivery is `SENDING`, and permanently fences token restoration and delivery requeue after a committed run. The run and receipt are immutable; a retry checks the scope and remaining sendable rows. Notification delivery history, provider receipts, preferences and consents remain governed separately. The operation does not claim final erasure or revoke a provider call already in flight.

Disposable PostgreSQL tests cover missing policy, active hold, a queued worker claim, country/subject isolation, runtime privilege, retry, reintroduction, provider receipt retention and rollback refusal. The complete source-matched backend gate passes all 27 PostgreSQL targets and 151 fresh/rollback migrations. The redeployed local stack passes health, 264 API checks and 85 regional/private-review journeys. No persistent account scrub was executed.

The media ECS task policy now grants bucket-level `ListBucket` for readiness, object-level `GetObject`/`PutObject`/`DeleteObject`/`AbortMultipartUpload` for its current adapter, and S3-bound `Decrypt`/`GenerateDataKey` on the configured data KMS key. Local Terraform formatting and validation pass. No AWS deployment or IAM simulator proof exists yet. The media bucket uses versioning: the current unversioned delete can leave noncurrent bytes. A legal-hold-aware, version-aware purge and independent restore/retention proof are required before media can issue terminal `ERASED` or `NO_DATA` evidence.

Messaging outbox envelopes currently accept arbitrary JSON without an authoritative subject/country key. Outbox delivery and inbox deduplication must be preserved; a bulk subject scrub cannot safely identify or remove all copies. Producer-bound privacy metadata, legacy mapping, replay policy and JetStream copy handling remain required before messaging erasure can be accepted.
